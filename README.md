# FinSight

FinSight is a research and simulation platform for exploring market data, portfolio valuation, risk, and reproducible strategy experiments. It is educational software, not a brokerage, investment adviser, or source of financial advice. Sample OHLCV rows generated by the development endpoint are synthetic.

## Stack and architecture

- Spring Boot 4, Java 25, Maven, Spring Data JPA, PostgreSQL
- React 19, Vite, JavaScript, CSS
- REST controllers delegate market data, analytics, backtesting, portfolio valuation, and experiment persistence to focused services/repositories.

## Features

- Security and OHLCV market-data storage and date-range retrieval
- Total return, daily returns, annualized volatility, drawdown, Sharpe, Sortino, and historical VaR
- Buy & Hold and SMA crossover backtests with configurable fees and slippage
- Virtual portfolio valuation with cash, quantity, average price, market value, P&L, and weight
- PostgreSQL-backed experiment history containing configuration and headline results
- Responsive dashboard views for overview, market data, portfolio, backtesting, risk, and experiments

## API overview

- `GET /api/health`
- `GET /api/securities`, `POST /api/securities`
- `GET /api/market-data/{symbol}?from=YYYY-MM-DD&to=YYYY-MM-DD`
- `POST /api/market-data/generate/{securityId}` for synthetic development data
- `GET /api/analytics/{symbol}?from=YYYY-MM-DD&to=YYYY-MM-DD`
- `POST /api/backtests`
- `POST /api/portfolios/valuation`
- `GET /api/experiments`, `GET /api/experiments/{id}`, `POST /api/experiments`

## Run locally

Create PostgreSQL database `finsight_db`, then set the environment variables described in `backend/finsight-backend/.env.example` in your shell. `DB_PASSWORD` is required; no database password is stored in the repository. From `backend/finsight-backend` run:

```powershell
./mvnw.cmd spring-boot:run
```

From `frontend`, copy `.env.example` to `.env` if needed, run `npm install`, then run:

```powershell
npm run dev
```

Set `FRONTEND_ORIGINS` to a comma-separated list when the frontend is hosted somewhere other than the local Vite origins.

For deployment, set `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `SERVER_PORT`, `FRONTEND_ORIGINS`, and `VITE_API_BASE_URL` through the hosting platform's environment configuration. For Neon, use a JDBC URL for `neondb` with `sslmode=require`. The React production build can be served by a static host such as Vercel, while the Spring Boot service connects to managed PostgreSQL.

## Backtesting methodology

Signals use only the current and prior closing observations. SMA crossover orders are executed at the signal close with configurable percentage slippage and transaction fees. Equity is marked to the close each trading day. This is a simple educational execution model and does not represent liquidity, taxes, market impact, or broker fills.

## Limitations and future work

Prices currently use `double` for MVP simplicity; production financial accounting should use `BigDecimal`. Portfolio valuation currently supports a single holding request and is not persisted. Authentication, richer order models, CVaR/stress testing, corporate actions, and richer charting can be added later. No endpoint connects to real-money trading.
